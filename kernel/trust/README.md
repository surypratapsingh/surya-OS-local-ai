# Trust Root

This directory holds cryptographic material for verifying NOVA releases.

## Contents

- **root-key.pub** (generated by owner, offline)  
  Ed25519 public key for verifying release signatures.  
  **Must be committed to git.** This is the trust root.

## Trust Chain

```
Owner (offline)
  └─ Generates Ed25519 keypair
  └─ Keeps private key secure (never on network)
  └─ Publishes public key here (root-key.pub)

Build machine
  └─ Builds NOVA
  └─ Computes SHA256(nova.hdd)
  └─ Transfers hash to offline machine

Offline machine
  └─ Signs hash with private key
  └─ Returns signature to build machine

Deployment machine (or NOVA)
  └─ Verifies signature against root-key.pub
  └─ Only boots if signature is valid
```

## Workflow

1. **Owner** (offline, once):
   ```bash
   # On offline machine
   python3 ../tools/sign-release.py keygen
   ```
   Creates `root.priv` (keep safe, never expose) and outputs public key.

2. **Developer** (connected, per release):
   ```bash
   # On build machine
   python3 ../tools/prepare-release.py --version 1.0.0
   # Copy nova-release-hash.txt to USB
   ```

3. **Owner** (offline, per release):
   ```bash
   # On offline machine with private key
   python3 ../tools/sign-release.py nova-release-hash.txt root.priv 1.0.0
   # Copy nova-release-signature.txt to USB, return to build machine
   ```

4. **Developer** (connected, per release):
   ```bash
   # On build machine
   python3 ../tools/verify-release.py
   # If verified, proceed with installation
   ```

## Security Notes

- The private key (`root.priv`) should **never** be on a network-connected machine
- The public key (`root-key.pub`) should be committed to the repository
- Every release must be signed offline before deployment
- Signatures are validated before installation (prevents tampering in transit)
