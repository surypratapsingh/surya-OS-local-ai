## Shared rules

Rules 1 to 11 of `docs/queue-2026-11-03.md` and rules 12 to 14 of `docs/queue-2026-11-06.md` apply unchanged. Three rules are new:

15. **How to read a planted fault.** A plant is **CAUGHT** when at least one test or check turns red because of it. Caught is the good outcome: it shows the suite can fail. A plant that leaves every test green is **MISSED**, and that is a finding. Write one line per plant: `P<n> <what you changed> -> CAUGHT by <test name>` or `P<n> <what you changed> -> MISSED`. A review ends `VERDICT: FAIL` only if a plant is missed, a claim is false, or the code breaks an `AGENTS.md` invariant. All plants caught and no false claim found means `VERDICT: PASS`, with any findings listed.
16. **No verdict without its file.** Report an item as done only after its review log or code is committed and pushed, and name the commit hash in your message. Reporting a verdict for an item with no committed file breaks `AGENTS.md` rule 5.
17. **Red `main` comes first.** Before each item, run `gh run list --branch main --workflow check --limit 3`. If `check` is red because of a file you hold, fixing that is your next item.
